# 后台管理问题排查与修复说明

更新时间：2026-07-06

本文记录本次后台管理系统排查结果、已修复内容和上线后的验证方式。

## 1. 计划管理没有计划

原因：移动端原来有本地 SQLite 内置计划，但后端 `training_plans` 只保存用户同步上来的计划，新的服务端数据库没有系统内置计划，所以后台计划管理为空。

修复：
- 新增后端系统计划目录。
- `npm run db:seed` 会写入系统内置计划到 `training_plans`。
- `/api/admin/plans` 增加系统目录兜底，即使还没有执行 seed，也不会返回空列表。
- 新增只读接口：`GET /api/catalog/system-plans`。

## 2. 动作库为空

原因：移动端原来有本地动作 seed，后端 `exercises` 只保存用户同步动作，新的服务端数据库没有系统动作库。

修复：
- 新增后端系统动作目录。
- `npm run db:seed` 会写入系统内置动作到 `exercises`。
- `/api/admin/exercises` 增加系统目录兜底。
- 新增只读接口：`GET /api/catalog/system-exercises`。

## 3. 在线同练房间为空

原因：数据库已有 `training_rooms`、`training_room_members`、`training_room_events`，后台也能查询，但原来没有应用侧创建、加入、事件上报、结束房间的 API，所以没有数据进入房间表。

修复：新增在线房间 API。

- `POST /api/groups/:id/training-rooms`：创建或复用当前小组在线房间。
- `GET /api/groups/:id/training-rooms/current`：读取当前小组在线房间。
- `GET /api/training-rooms/:id`：读取房间详情、成员和事件。
- `POST /api/training-rooms/:id/join`：加入房间。
- `POST /api/training-rooms/:id/events`：写入训练房间事件。
- `POST /api/training-rooms/:id/leave`：离开房间。
- `POST /api/training-rooms/:id/end`：结束房间。

说明：服务端能力已经补齐，移动端如果还没有调用这些接口，仍需要在移动端接入后才会产生实时房间数据。

## 4. 176 与 3716 账号数据混用

现状判断：项目里已有移动端归属修复和服务端同步防串号逻辑，用于避免再次把其他账号的数据同步到当前账号。但历史已经写错的用户、小组、成员关系仍需要按具体记录修正。

本次修复：
- 后台“数据修正”从只写日志改成真实写库。
- 修正会自动读取修改前的值，不需要管理员手填旧值。
- 每次修正都会写入 `admin_corrections` 和 `admin_audit_logs`。
- 支持回滚，回滚会把 `before_value` 写回目标业务表。
- 小组关系可修正 `status`、`role`、`user_id`、`left_at`，可用于处理错误成员绑定。

建议处理流程：
1. 在后台用户页分别搜索 176、3716，记录两个账号的 `users.id`、手机号、练刻 ID。
2. 在小组详情或数据库里确认错误的 `group_members.id`。
3. 用“数据修正”修正 `group_members.user_id`、`status` 或 `left_at`。
4. 如果是用户昵称或练刻 ID 显示错误，用“用户资料”修正 `nickname` 或 `liftmark_id`。
5. 修正前建议先备份生产数据库。

## 5. 访问 `/uploads/avatars/` 返回 Route not found

原因：头像文件地址应为 `/uploads/avatars/{filename}`，直接访问目录不是具体文件。原来静态文件服务没有给目录地址单独返回说明，所以显示 404。

修复：
- 新增 `/uploads/avatars` 和 `/uploads/avatars/` 探测路由。
- 直接访问目录时会返回可读说明。
- 真实头像文件仍然通过 `/uploads/avatars/{filename}` 访问。

## 6. 数据修正功能难用且无法成功

原原因：旧实现只向 `admin_corrections` 写记录，并没有更新业务表，所以看起来“提交了但没改成功”。

修复：
- 字段从后端白名单返回，前端以下拉方式选择。
- 不再要求管理员填写旧值，旧值由服务端从数据库读取。
- `afterValue` 会按字段类型解析：
  - 数字字段：填写数字。
  - 布尔字段：填写 `true` / `false`。
  - 时间字段：填写 ISO 时间或可解析日期；需要清空时填写 `null`。
  - 字符串字段：填写目标文本。
- 支持真实回滚。

已接入的修正目标包括：用户资料、会员权益、小组、小组成员关系、成员档案、训练记录、训练组数据、计划、动作、同步状态、订单权益、激活码记录。

## 7. 公告系统是否接入

结论：公告系统已经接入，但有展示条件。

已有能力：
- 后端：`GET /api/announcements/current`。
- 后台：公告列表、新建、编辑、发布状态管理。
- 移动端：Today 页会读取当前公告并弹窗展示。

看不到公告的常见原因：
- 公告状态不是 `published`。
- 当前时间不在 `starts_at` / `ends_at` 范围内。
- 当前用户已经读过该公告。
- 用户没有进入会触发公告读取的 Today 页。

## 8. 下发会员不提示失败，也没成功

原因：
- 后台页面传入的来源包含 `manual`、`beta`、`campus` 等，但后端只允许 `activation_code`、`admin_grant`、`payment_reserved`，请求会被校验拦截。
- 后端只按 `users.id` 查用户，输入手机号或练刻 ID 会找不到用户。

修复：
- 后端允许后台页面已有的发放来源。
- 会员下发支持输入用户 ID、手机号、邮箱、练刻 ID 或唯一昵称。
- 会员页搜索也支持练刻 ID 和邮箱。
- 前端文案改为“用户标识”，避免误以为只能填内部用户 ID。

## 上线步骤

在服务器上更新代码后执行：

```bash
cd apps/liftmark-api
npm run db:migrate
npm run db:seed
npm run build
```

然后重启 API 服务和后台管理服务。

## 验证清单

- 后台计划管理能看到系统内置计划。
- 后台动作库能看到系统内置动作。
- 访问 `/uploads/avatars/` 返回说明，不再返回 route not found。
- 后台会员下发可用用户 ID、手机号、练刻 ID 或邮箱成功发放。
- 数据修正提交后目标业务表实际变化，并能回滚。
- 创建在线房间后，后台在线同练房间列表能看到对应房间。
- 发布一条有效时间内的公告后，移动端 Today 页能读取并展示。
