# 训练总结流程

更新时间：2026-06-30

## 1. 流程目标

训练完成后统计完成度、参与成员完成情况、PR/预估 1RM、下次建议和小组成员数据同步确认边界。

## 2. 参与模块

- workout
- progression
- history
- weight

## 3. 前置条件

- 本地 SQLite 可用。
- 默认 seed 数据已按需初始化。
- UI 只触发流程，不承载核心业务规则。

## 4. 主流程

1. 用户点击完成训练。
2. 更新 workout_session.status=completed 并写入 finished_at。
3. 按 session sets 反推本次参与成员，并统计每个参与成员和每个动作的完成情况。
4. 调用 progression 模块生成 progression_suggestions。
5. 计算 PR 或预估 1RM 展示项。
6. 跳转训练总结页。
7. 总结页展示完成度、成员头像、成员表现、表现分析和小组同步确认卡。
8. 如果是小组本机记录，其他成员数据在确认前仅保存在本机；发送确认当前为预留流程，不执行远程同步。
9. 如果本次训练包含替换、加做、跳过或临时动作，总结页展示“本次训练有调整”卡片，并让用户选择仅保存本次记录或同步到当前用户计划。

## 5. 数据读写

写入或重点影响：

- workout_sessions
- progression_suggestions

## 6. 异常与边界

- 未完成 set 应保留未完成状态。
- 建议只能追加保存，不能覆盖训练记录。
- 成员确认和云同步未接入前，不得把其他成员数据自动写入远程账号。
- 同步本次调整到计划只允许修改用户计划；系统方案或系统来源计划必须提示不可直接写回。
- 同步到计划时以 session 的 `week` 和 `weekday` 定位计划日，替换动作更新 exerciseId，加做组提升 sets，跳过动作可移除该计划日动作，临时动作追加到该计划日末尾。

- 修改本流程涉及逻辑时，同步检查相关模块文档。
