# History 测试计划

更新时间：2026-07-07

## 2026-07-07 补充

- 日期筛选快捷区应显示“自定义”按钮；点击后应打开日历式范围弹层，不能回退为手动输入起止日期。
- 趋势图横轴不应显示未训练时间桶；数据为 0 的日期 / 周不应占用横轴标签，也不应画假点。
- 趋势图默认不应在横轴上方展示点位数值；点击有效点位后才显示 tooltip 和高亮数值。
- 训练分析页图表顺序应为：单个动作 1RM 趋势、单个动作训练容量趋势、训练量趋势、训练频率趋势。
- 训练分析页 1RM 趋势和单个动作容量趋势应分别支持动作筛选，切换后只影响对应图表。
- 补录页路由应保持无系统标题、无系统返回按钮。
- 记录首页的“训练趋势”整张组件都应可点击进入对应分析页；小组记录视角不应再显示独立“小组分析”和“出勤率”按钮。
- 小组分析页顶部时间筛选右侧应有“动作对比”和“出勤率”入口；页面内部两组训练量 / 完成率 / 活跃度切换控件应居中、不挤压标题行。
- 小组分析无训练记录时，最近训练记录区域应展示空态，不显示空时间或空计划占位。
- 小组洞察每次从更大的数据驱动候选池中展示 4 条，文案应能反映成员贡献、完成率、出勤覆盖、动作样本或训练量峰值等实际情况。

## 2026-07-06 补充

- 日期筛选应支持快捷范围和自定义范围入口；2026-07-07 起自定义范围使用日历点选弹层。
- 记录首页右上角补录入口应为紧凑图标按钮，点击进入补录页。
- 折线图有效点位点击后应显示 tooltip；点击空点不应展示假数据。
- 稀疏训练数据不应把折线拉到 0；跨非训练日期时应连接相邻有效训练点。
- 个人训练分析动作筛选应来自当前成员真实练过的动作；选中动作后核心动作区域只显示该动作趋势。
- 小组动作对比动作筛选应支持搜索、肌群和器械过滤；切换动作后排行、趋势和记录列表同步刷新。
- 小组分析成员贡献切换训练量 / 完成率 / 活跃度时，排序、主指标、进度条和趋势图都要改变。
- 成员分析右上角切换成员后，概况、指标、趋势、优势动作和训练列表同步刷新。
- 小组分析相关头像应优先使用 `member_profiles` 头像缓存，账号头像更新后当前训练成员应能同步显示。

## 2026-06-30 补充

- 历史首页个人趋势、小组趋势、小组动作趋势应按实际训练记录或训练日期显示，不应按自然日补零。
- 图表需显示 Y 轴刻度和单位。
- 周趋势应使用周起始日期，不出现旧的相对周文案或“第 N 次”标签。
- 动作历史、小组动作详情和训练分析 1RM 图表 X 轴应使用真实日期；同一天多次训练可追加短后缀区分。
- 训练分析页需能切换 4 / 8 / 12 周。
- 个人动作详情 `/history/exercise/[exerciseId]` 需展示容量、最佳重量、估算 1RM、RPE 趋势和最近有效组。
- 小组记录默认展示总览，不默认展示某个动作。
- 小组动作选择器应列出真实练过的 `exerciseId`，点击后图表和详情页均按该真实动作过滤。

## 1. 单元测试范围

- 训练完成后历史列表可见。
- 按成员和动作筛选能返回正确记录。
- 替换动作历史能显示原动作与替代动作。
- 小组动作列表来自 `workout_exercise_records.exercise_id`，不是硬编码动作类别。
- Epley 公式预估 1RM。
- 最近 5 次训练重量、完成率、完成情况、预估 1RM 趋势。
- PR 接近度和疲劳提示仅作为建议输出。

## 2. 集成测试范围

- Repository 与 SQLite 表结构联调。
- 与依赖模块的数据流联调：workout, member, exercise, progression, weight。
- 与被依赖模块联调：export, progression。

## 3. E2E 测试范围

- 首次使用后能进入今日训练。
- 成员、计划、训练、历史和导出闭环不丢数据。
- 断网时训练流程仍可完成。

## 4. 必测场景

- 训练完成后历史列表可见。
- 按成员和动作筛选能返回正确记录。
- 替换动作历史能显示原动作与替代动作。
- 近期表现接近 PR 时显示“近期表现接近 PR，可考虑小幅尝试”。
- 连续未完成 或连续未完成时提示“近期疲劳偏高，建议维持或减量”。

## 5. 边界场景

- 历史记录必须展示训练当时的计划快照，而不是当前计划。
- 第一版复杂图表延后，避免拖慢 MVP。

- 修改数据结构后，检查 `docs/database/schema.md`。
- 修改 Repository 后，检查 `docs/api/local-repository-api.md`。
