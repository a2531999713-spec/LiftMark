# v2.8.0 动作级训练进阶建议

## 产品与规则

建议以成员 + 动作 + 已完成训练为粒度，采用确定性规则，不修改计划或历史训练。`strength` 优先使用动作规则、快照/计划目标和固定/百分比处方；全部完成加一个器械档位，90% 以上未完全完成维持，一次明显失败为维持或降重，连续两次低完成率降一个档位，连续三次低于 60% 减量。`hypertrophy` 使用 repMin/repMax 双进阶：全部到上限加重，到下限但未全到上限继续加次数，连续两次低于下限降重。处方不足时使用保守 general 规则。

重量增量优先成员器械配置（杠铃/哑铃），再回退用户偏好与 2.5kg 安全默认值，统一复用现有重量取整。自重动作不会伪造 kg 建议。

## 时序、作用域与同步

训练结束仍先完成本地 SQLite 并进入总结；训练报告、建议生成、同步均在后台执行。建议 ID 固定为 `progression_{sessionId}_{memberId}_{exerciseId}`，重复调用更新同一行，队列按实体/本地 ID 合并，因此可重算且不重复入队。

Repository 对建议读写限制 `owner_user_id + workout_sessions.group_id + group scope + member + exercise`，历史表现为一次批量查询，最多取每对成员/动作最近三次，不产生动作循环 N+1。pull 仅在关联 session、同组成员和动作均对当前账号可见时应用建议。

## 页面和安全边界

- 总结页在后台生成期间显示“正在生成下次建议”，失败不影响总结或报告，可重新生成。
- 报告详情按成员展示建议，旧报告无建议显示空状态。
- 训练执行页只显示当前成员/动作的最新、早于当前 session 的建议；应用仅更新当前 in-progress session 的当前成员未完成组 `planned_weight`，不改计划、完成组、其他成员或历史数据。
- 单动作历史页显示当前成员、当前小组最近 5 条建议。

建议仅供训练安排参考；身体不适或动作质量下降时优先降低强度。未新增 SQLite/PostgreSQL migration、API 或服务器部署。

## 已知限制与验收

仍保留 v2.7.2 的计划页 ActiveTrainingContext 收敛、计划页最近训练 N+1、部分分析选择 Sheet 与旧文档清理事项。本版自动化覆盖领域规则、取整、空组、scope 和训练结束本地关键路径；真机与 Android arm64 构建需在隔离测试账号继续执行。
