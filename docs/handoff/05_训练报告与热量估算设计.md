# 05 训练报告与热量估算设计

## 2026-07-11 当前实现结果

- `/report/[sessionId]` 已由训练结束页与历史详情页接入，展示整场、多成员、动作和组级明细。
- 报告读取、fallback 汇总、强度和热量估算集中在 domain/application/repository，不在页面重复公式。
- 缺失体重按缺失参与者使用 65kg 默认估算，UI 显示估算范围、参考说明和完善体重提示。
- 旧训练无 report 时只读汇总，不因查看页面写回数据库；报告 upsert 按当前 owner + session 幂等。
- canonical 实施记录：`docs/03-architecture/plan-cycle-report-history-implementation-2026-07.md`。

## 一、训练结束必须生成报告

每次训练结束后都应该生成训练报告，而不是只保存原始记录。

训练报告用于：

```text
1. 用户训练反馈。
2. 历史记录展示。
3. 计划周期统计。
4. 数据分析。
5. 后续 AI 总结。
```

## 二、训练报告内容

第一版报告包含：

```text
训练日期
训练计划名称
训练部位
训练时长
总训练量
完成动作数
完成组数
总次数
估算热量
主要动作表现
个人备注
```

## 四、热量估算

可以做，但必须标明是估算值。

不要显示：

```text
精确消耗 237 kcal
```

应该显示：

```text
预计消耗 180–260 kcal
```

## 五、估算算法

第一版使用 MET 公式：

```text
热量 kcal = MET × 体重 kg × 训练时长 h
```

力量训练 MET 建议：

```text
轻度：3.5
中等：5.0
高强度：6.0
```

如果用户没有体重：

```text
使用默认体重 65 kg
并在 UI 上标注：完善体重后估算更准确
```

## 六、训练强度判断

可用以下因素估算：

```text
训练时长
总组数
总训练量
平均组间休息
是否接近力竭
动作类型
```

第一版可以简单分：

```text
low
medium
high
```

