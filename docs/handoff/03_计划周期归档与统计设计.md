# 03 计划周期、归档与统计设计

## 2026-07-11 当前实现结果

- 已实现计划页周期卡和 `/plan/cycle/[cycleId]` 周期总结页，包含周期状态、日期、完成率、训练量、组数、次数、时长、估算热量、报告数量和周期训练列表。
- 已实现 `active → completed → archived` 显式转换与二次确认；重复完成、重算、归档复用同一 owner + cycle summary，不删除或重绑历史训练。
- summary 优先读取训练报告，缺失报告时按同一 session 明细降级聚合；当前没有可靠 skip 事件，跳过次数不做推测。
- 未新增 migration，复用 SQLite v23 的 `plan_cycles` / `plan_cycle_summaries` 与现有同步 registry。
- canonical 实施记录：`docs/03-architecture/plan-cycle-report-history-implementation-2026-07.md`。

## 一、为什么必须做

力量训练计划通常有明确周期，比如：

```text
4 周增肌计划
8 周力量提升计划
12 周周期训练
```

计划执行完后不能只留普通训练历史，应该生成一个“已完成计划周期”和周期统计。

## 二、计划状态

TrainingPlan 建议增加状态：

```text
draft
active
paused
completed
archived
abandoned
```

含义：

```text
draft：草稿，未开始
active：当前执行中
paused：暂停
completed：已完成，但还未归档
archived：已归档
abandoned：中途放弃
```

## 五、周期结束逻辑

当计划达到周期末尾时，App 应提示：

```text
当前计划周期已完成
是否归档并查看周期总结？
```

用户可选择：

```text
1. 归档计划周期。
2. 复制为下一周期。
3. 调整后继续执行。
4. 暂不处理。
```

## 六、第一版必须做

```text
1. plan status 字段。
2. plan cycle 字段或表结构。
3. 计划完成后的归档入口。
4. 基础统计：训练次数、完成率、总训练量、总组数、总时长。
5. 训练历史能按计划周期筛选。
```
